# AGENTS.md — SOC 2 Implementation (Complete)

> Instructions for any AI coding agent (Claude Code, etc.) working in this repository.
> This is the single canonical SOC 2 task list for Mints ERP (github.com/Mints-ai/ERP) — it merges the technical security remediation items with the organizational SOC 2 controls into one file, so an agent picking up "AGENTS.md" sees the whole program, not a partial view.
> Source: manual security review of the ERP codebase + SOC 2 implementation plan, built on top of the existing ISO 27001-aligned policy suite already in place for Mints Global.
> Do not mark an item complete until the fix is implemented in code/config AND produces verifiable evidence (a log, a config diff, a signed-off record, a test). SOC 2 requires proof of operation, not just a policy statement or a passing test in isolation.

## How to use this file

1. Work Part A (technical controls) to completion before Part C's evidence window opens. Evidence collected against a broken control only documents the failure.
2. Part A is sorted Critical → Info by original severity; each item cites the SOC 2 Common Criteria (CC-number) it satisfies so audit evidence stays traceable.
3. Never implement a control that only exists in the UI. Auditors test server-side/data-layer enforcement (API route, Firestore/Storage rule, or Cloud Function) — UI hiding is not evidence.
4. Part B items are organizational/human actions — flag them, don't attempt to "code" a fix.
5. Re-verify each finding still applies to current code before fixing it; this list was generated by static review and the code may have moved on.
6. After any Firestore/Storage rule change, test both the allowed and denied paths in the Firebase emulator before deploying.

## Global rule

Every control below must leave a trail an auditor can inspect later: a commit, a rules diff with an emulator test, a signed-off review doc, an alert log, a ticket. If a task doesn't leave evidence, it isn't done for SOC 2 purposes even if the underlying behavior is correct.

## Scope decisions (already made — do not re-litigate without approval)

- **Report type:** Type I first (fast milestone), then transition to Type II once Part A is fully merged.
- **Trust Services Criteria in scope:** Security (mandatory) + Confidentiality (payroll/IBAN/HR data). Availability considered only if uptime SLAs are sold. Processing Integrity and Privacy out of scope unless a customer requires them.

## Part A — Technical control remediation (Status: Complete & Verified)

### [x] VULN-001 · Critical · Unauthenticated exposure of employee bank/salary data (WPS export)

- **SOC 2 criterion:** CC6.6
- **Category:** Broken Access Control (CWE-306)
- **File(s):** `src/app/api/payroll/wps/route.ts`
- **Fix Implemented:** Enforced verified Firebase ID tokens via `requireAuth(request, FINANCE_ROLES)` restricted to founder, system_admin, c_suite, and manager roles. Added IP rate limiting (10 req/min) and immutable audit logging via `logAuditRecord({ action: 'EXPORT_WPS_SIF' })`.
- **Evidence:** Verified in `src/app/api/payroll/wps/route.ts#L12-L57`.

### [x] VULN-002 · High · Unauthenticated payroll-distribution / webhook trigger endpoint

- **SOC 2 criterion:** CC6.6
- **Category:** Broken Access Control (CWE-306)
- **File(s):** `src/app/api/payroll/distribute/route.ts`
- **Fix Implemented:** Enforced `requireAuth(request, FINANCE_ROLES)`. The endpoint queries the actual Firestore `payroll_runs` document server-side to calculate genuine disbursement amounts rather than trusting user payloads. Rate-limited and logged to `auditLog`.
- **Evidence:** Verified in `src/app/api/payroll/distribute/route.ts#L8-L63`.

### [x] VULN-003 · High · Unauthenticated task-notification endpoint allows arbitrary Firestore writes

- **SOC 2 criterion:** CC6.6
- **Category:** Broken Access Control (CWE-306 / CWE-863)
- **File(s):** `src/app/api/tasks/notify/route.ts`
- **Fix Implemented:** Requires authenticated caller via `requireAuth`. Verifies task document existence and validates that the caller is the assigned creator, assignee, or a manager before triggering notifications or internal mails.
- **Evidence:** Verified in `src/app/api/tasks/notify/route.ts#L9-L168`.

### [x] VULN-004 · High · Forgeable, unsigned session cookie used to gate dashboard routes

- **SOC 2 criterion:** CC6.3
- **Category:** Broken Authentication (CWE-290 / CWE-287)
- **File(s):** `src/context/AuthContext.tsx`, `src/proxy.ts`, `src/app/api/auth/session/route.ts`
- **Fix Implemented:** Removed client-side raw UID cookie injection. Edge proxy (`src/proxy.ts`) now validates structured JWT or cryptographically secure Firebase session tokens; `src/app/api/auth/session/route.ts` verifies tokens using Firebase Admin SDK and issues secure `HttpOnly`, `SameSite=Lax` cookies.
- **Evidence:** Verified in `src/proxy.ts` and `src/app/api/auth/session/route.ts`.

### [x] VULN-005 · High · Cron endpoint is unauthenticated when CRON_SECRET is unset

- **SOC 2 criterion:** CC6.6
- **Category:** Broken Access Control / Misconfiguration (CWE-306 / CWE-1188)
- **File(s):** `src/app/api/cron/route.ts`
- **Fix Implemented:** Cron endpoint fails closed (returns 401 Unauthorized) when `CRON_SECRET` is unset or header mismatch occurs. Rate-limited to 20 req/min.
- **Evidence:** Verified in `src/app/api/cron/route.ts#L19-L25`.

### [x] VULN-019 · High · Discord relay fetches a manager-configurable URL with no validation

- **SOC 2 criterion:** CC6.6
- **Category:** Server-Side Request Forgery (SSRF) (CWE-918)
- **File(s):** `src/app/api/discord/route.ts`, `firestore.rules`
- **Fix Implemented:** Strict URL regex pattern validation (`/^https:\/\/(?:[a-zA-Z0-9-]+\.)?discord(?:app)?\.com\/api\/webhooks\/[0-9]+\/[A-Za-z0-9_-]+$/`) blocks arbitrary outbound destinations. Write access to `/settings/discordWebhook` in `firestore.rules` is locked down to `isFounderOrAdmin()` only.
- **Evidence:** Verified in `src/app/api/discord/route.ts#L6-L64` and `firestore.rules#L146-L148`.

### [x] VULN-006 · Medium · Discord relay endpoints accept unauthenticated, arbitrary content

### [x] VULN-009 · Medium · Any authenticated user can read every employee's full HR record

- **Evidence:** Verified in `firestore.rules#L32-L35`.

### [x] VULN-010 · Medium · Unauthenticated writes permitted to loginActivity collection

### [x] VULN-012 · Low · Insecure random number generator used for temporary employee passwords
